<task type="auto">
  <name>Task 2: Write build.sh and achieve zero-error build</name>
  <files>build.sh</files>
  <action>
    Create build.sh at the root of THIS project directory (the sibling of PX4-Autopilot):

    ```bash
    #!/usr/bin/env bash
    # build.sh — single-command Docker build for orqa/h7quadcore
    # Requires: Docker running, PX4-Autopilot cloned at ../PX4-Autopilot (tag v1.15.4)
    # Usage: ./build.sh [make-target]
    #   Default target: orqa_h7quadcore_default
    #   Bootloader:     ./build.sh orqa_h7quadcore_bootloader
    set -euo pipefail

    SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
    PX4_SRC="$(cd "${SCRIPT_DIR}/../PX4-Autopilot" && pwd)"
    CCACHE_DIR="${HOME}/.ccache"
    TARGET="${1:-orqa_h7quadcore_default}"

    if [ ! -d "${PX4_SRC}" ]; then
      echo "ERROR: PX4-Autopilot not found at ${PX4_SRC}"
      echo "Clone PX4-Autopilot at tag v1.15.4 as a sibling directory of this project."
      exit 1
    fi

    mkdir -p "${CCACHE_DIR}"

    echo "Building target: ${TARGET}"
    echo "PX4 source: ${PX4_SRC}"

    docker run --rm \
      --env=LOCAL_USER_ID="$(id -u)" \
      --env=CCACHE_DIR="${CCACHE_DIR}" \
      --volume="${PX4_SRC}:${PX4_SRC}:rw" \
      --volume="${CCACHE_DIR}:${CCACHE_DIR}:rw" \
      --workdir="${PX4_SRC}" \
      px4io/px4-dev-nuttx-focal:2022-08-12 \
      /bin/bash -c "make ${TARGET}"
    ```

    Make it executable: chmod +x build.sh

    Then run the build and fix all errors/warnings until the build is clean:
      ./build.sh 2>&1 | tee build.log

    Common issues to resolve:
    - Any remaining Matek-specific string literals in CMakeLists.txt or .px4board that cause
      CMake configure errors — update to orqa equivalents
    - Any symbol collision from header guard renames — verify grep found all occurrences in Task 1
    - Missing board_id registration warning — acceptable for Phase 1 (private board_id 1099)

    After a clean build, also build the bootloader to confirm it compiles:
      ./build.sh orqa_h7quadcore_bootloader

    Zero errors, zero warnings is required. If warnings appear, fix them — do not suppress.
    Deprecation notices from the CMake build system itself (not from board source) are
    acceptable if they appear in the NuttX submodule and are outside the board target files.
  </action>

    - USB-C cable connected to the Orqa H7 QuadCore

    Step 1 — Enter ST ROM DFU mode:
      Hold the BOOT button on the board, plug USB-C, then release BOOT after ~2 seconds.
      Run: dfu-util -l
      Expected: Device shown as [0483:df11] (ST DFU VID:PID). If absent, retry BOOT sequence.

    Step 2 — Flash PX4 NuttX bootloader:
      dfu-util -a 0 --dfuse-address 0x08000000 -D \
        ../PX4-Autopilot/build/orqa_h7quadcore_bootloader/orqa_h7quadcore_bootloader.bin
      Expected: "File downloaded successfully" with no errors.

    Step 3 — Reboot into PX4 bootloader:
      Unplug USB-C and reconnect (no BOOT button this time).
      The PX4 bootloader enumerates briefly — you have ~5 seconds before it boots into
      application (which may be empty on first flash; board may appear unresponsive).

    Step 4 — Flash application firmware via QGroundControl:
      Open QGroundControl, go to Vehicle Setup, Firmware.
      Select "Advanced settings" then "Custom firmware file".
      Browse to: ../PX4-Autopilot/build/orqa_h7quadcore_default/orqa_h7quadcore_default.px4
      Click OK and wait for upload to complete.
      Alternative (CLI): ./build.sh orqa_h7quadcore_default upload
